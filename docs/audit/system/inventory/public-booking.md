## Evidence Rules

- `COMPLETE_VERIFIED` requires fresh executable evidence for the complete reachable behavior.
- Source inspection without a successful API/browser journey is not promoted to complete.
- Severity is `P0` for booking/inventory integrity or externally sellable inactive inventory,
  `P1` for release-significant behavior and `P2` for product quality or performance.
- Search, detail and booking must use the same property, room-type, room-state, date,
  capacity, price and payment-readiness rules.

## Required Remediation Order

T149 must order public-booking remediation as follows:

1. Close the P0 sellable-inactive-room-type, booking-idempotency and overbooking-evidence
   boundaries in PUB-016, PUB-023 and PUB-024.
2. Establish one public eligibility and availability policy and retire/delegate the legacy search
   endpoint in PUB-007, PUB-012 and PUB-015 while preserving the completed PUB-030 harness.
3. Make filter, price, capacity and quote behavior use the same eligible room type from search
   through locked reservation creation.
4. Align configured payment methods, build complete property details, and finish one-type then
   mixed-type multi-room journeys.
5. Resolve anonymous booking identity/privacy and optimize the nationwide discovery queries only
   after integrity and ownership are executable.

No production payment enablement, real-money journey, destructive guest cleanup or automatic
activation of unapproved inventory is authorized by these remediation tasks.
