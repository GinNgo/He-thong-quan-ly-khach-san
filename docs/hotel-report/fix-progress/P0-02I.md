## Error-envelope contract

| Trường | Ổn định cho client | Quy tắc |
|---|---|---|
| HTTP status | Có | Phân lớp 400/401/403/409/500 theo handler/security contract |
| `code` | Có | Client logic, navigation và retry phải ưu tiên trường này |
| `message` | Có về tính an toàn/mục đích; không phải exception text | Display-only, có thể được bản địa hóa; không lộ tài khoản, token hoặc chi tiết nội bộ |
| `path` | Có | Route xử lý request; không chứa stack trace |
| `correlationId` | Có nhưng động | Dùng hỗ trợ/observability; không hardcode UUID |
| `fieldErrors` | Có khi validation | Map field-level; `{}` cho generic invalid request |
| `retryable` | Có | Client chỉ retry khi server phân loại an toàn |
| `currentState` | Tùy chọn | Dùng cho conflict/state-aware recovery |
| timestamp | Không có trong DTO hiện tại | Nếu bổ sung sau này phải coi là động |

Frontend evidence:

- `error-interceptor.ts` dùng HTTP status và `error.code` cho 401/403/navigation, không so sánh generic message.
- Các form có thể hiển thị `fieldErrors` hoặc `message` với fallback; đây là display text, không phải khóa điều khiển.
- `async-action-coordinator` dựa vào `code`/`retryable`, không dựa vào exception message.

## Root cause và quyết định sửa

`GlobalExceptionHandler.handleBadRequest()` chủ đích không trả `IllegalArgumentException.getMessage()`. Nó chuẩn hóa lỗi thành 400, code `INVALID_REQUEST`, message an toàn `The request is invalid.`. Đây là contract đúng vì exception text có thể chứa dữ liệu nội bộ hoặc đầu vào nhạy cảm.

Test fixture vẫn mong raw exception message nên đã cũ. Thay đổi tối thiểu:

- Đổi expected message sang message public an toàn.
- Thêm negative assertion rằng response không chứa từ `fixture`, giữ kiểm tra chống rò rỉ.
- Giữ nguyên assertion status, code, correlation, fieldErrors, retryability, state và path.

Chỉ sửa `backend/src/test/java/com/hotel/security/AuthExceptionIntegrationTest.java`. Không sửa production/frontend.
