## Root cause

`src/test/resources/application-test.yml` correctly disables Flyway for Maven tests, but test resources are not included in the executable Spring Boot JAR. Running the packaged artifact with profile `test` therefore loaded no packaged profile override and fell back to base `application.yml`, where Flyway is correctly enabled for SQL Server at `classpath:db/migration`.

The migration directory is flat; all 56 files are SQL Server-oriented. There are no current `common`, `h2` or database-specific subdirectories. V1 proves the set is not H2-compatible.

- Production SQL Server configuration: **correct and preserved**.
- Maven test configuration: **correct for tests**.
- Packaged H2 runtime invocation/profile: **incorrect before fix**.
- Demo location bootstrap: not the first failure. After profile isolation it completed successfully, proving the previous H2 bootstrap incident was caused by inconsistent ad-hoc smoke overrides rather than a reproducible independent blocker.

## Minimal solution

Added `backend/src/main/resources/application-local-h2.yml`:

- Explicit H2 datasource.
- Hibernate `create-drop` disposable schema.
- Flyway disabled only in `local-h2`.
- E2E/demo/accommodation seed runners disabled; normal location import remains unchanged.
- Provider recovery disabled for isolated local smoke.

No migration was edited, moved, deleted, repaired or made H2-compatible. SQL Server continues using base Flyway configuration and all released migrations.
