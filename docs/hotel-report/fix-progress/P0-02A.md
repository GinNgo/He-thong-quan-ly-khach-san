## 6. Nguyên nhân gốc

`ChatControllerIntegrationTest` là class duy nhất trong nhóm dùng URL mặc định `mem:testdb` đồng thời có `@DirtiesContext(AFTER_CLASS)`. Do class chat có property set khác auth, Spring tạo một application context/Hikari pool riêng nhưng cả hai pool vẫn kết nối cùng named H2 database.

Khi chat kết thúc, `@DirtiesContext` đóng context. Hibernate `ddl-auto:create-drop` chạy schema teardown trên `testdb`. Cached auth context vẫn tồn tại nhưng database của nó đã bị context chat xóa. Registration hoặc auth chạy sau đó tái sử dụng cached context và truy vấn vào database rỗng.

Focused registration PASS vì trong JVM Maven riêng không có context chat đóng schema trước nó; Hibernate tạo schema mới khi context registration khởi tạo.

Đây là lỗi test isolation, không phải lỗi production registration, entity `EmailVerificationToken`, migration V52 hoặc transaction nghiệp vụ.

Stack trace làm sạch: `evidence/P0-02A-stack-trace-clean.txt`.

## 7. Thay đổi tối thiểu

Chỉ sửa annotation của `ChatControllerIntegrationTest`:

```java
"spring.datasource.url=jdbc:h2:mem:chat-controller;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE"
```

H2 lifecycle sau sửa:

- Auth/registration tiếp tục dùng `mem:testdb` và chia sẻ cached context hợp lệ.
- Chat dùng `mem:chat-controller` riêng.
- `@DirtiesContext` và Hibernate `create-drop` của chat chỉ teardown `chat-controller`.
- Không cần bỏ `@DirtiesContext`, thêm sleep/retry, tắt assertion hoặc đổi production behavior.
